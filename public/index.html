Bike Rental Demand Forecasting

Forecasting demand is only useful if you can act on it in time. This project builds a full MLOps pipeline that predicts hourly bike rental counts and surfaces them in a live dashboard. Three Kedro stages handle feature engineering (with lag features), CatBoost training and a continuous inference loop. The inference engine and dashboard run in separate Docker containers sharing a volume decoupled and independently restartable. Predictions are visualised in real time with an adjustable lookback window, containerised with Docker Compose, and deployed on Railway. The key design choice is separation of concerns: training, inference and visualisation are cleanly isolated, so any one piece can be swapped or adjusted without touching the others.

KedroCatBoostDashDockerRailway

Nairobi House Price Prediction

Property data in Kenya is fragmented and rarely structured. Rather than use a pre-packaged dataset, this project starts with a scraper that pulls live listings from Property24.co.ke, cleans the raw data, and trains an XGBoost model to predict prices across Nairobi's neighbourhoods. Location turned out to be the dominant signal — properties in Muthaiga cost over 30x more than comparable ones in Kitengela. The model is served through a Streamlit app where you enter bedrooms, bathrooms, size, and amenities and get a price estimate in KES with the key drivers explained. R² of 0.38 — honest about the limits of public listing data and a good argument for why richer features matter.

Atlas Travel Assistant

A conversational travel assistant that answers real questions: current weather, exchange rates, destination info — rather than giving static, pre-written responses. Built on FastAPI with LangChain orchestrating tool calls to a Groq-hosted Llama 3.3 70B model. The interesting constraint here was latency: Groq's inference speed makes the assistant feel responsive enough for actual use rather than a demo. Deployed as a production API on Railway.

A multiclass classifier that identifies glass types from physical composition data. The focus of this project isn't the dataset, it's the architecture: a modular Flask pipeline where training and prediction are fully separated, serialized with Dill to preserve the complete pipeline state. Built with TensorFlow. The kind of clean separation that makes a model actually swappable in production.

Maternal Health Risk Predictor

Classifies pregnancy risk into Low, Mid and High using clinical vitals. The pipeline follows the same Kedro structure as the Bike Forecasting project: feature engineering, CatBoost training and inference are separate, testable stages, with predictions surfaced through a real-time Dash dashboard. The domain matters here: a misclassification in a health context is expensive, which is why the multi-class framing and pipeline reproducibility are the right choices.
